# File uploads current state

## Что можем и какой сейчас механизм
- закачивать файлы с клиента на сервер целиком. Есть реализация на C# и TypeScript
- на сервере приёмом файлов занимается ChatMediaController
- также для загрузки аватаров на сервере есть AvatarPicturesController
- файл может быть загружен только целиком
- загружаемый файл сохраняется куда?, что за временное хранилище
- после загрузки данных файла запускается постпроцессинг для файлов изображений и видео
- после загрузки и обработки файла сервер возвращает клиенту MediaId и ContentId для обработанного файла и превью файла
- получив MediaId для всех приаттаченых файлов сообщения, клиент отправляет команду на сервер создать сообщение с аттачментами
 или обновить аттачменты, если сообщение прежде уже было создано с флагом `HasAttachmentUploads`
- IMediaBackend — база данных медиа (метаданные загруженных файлов и ссылка на contentId)
- ContentController — позволяет скачивать присоединённые файлы по ContentId, обращается в MediaBackend для получения метаданных, чтоб предоставить правильно представление файла
- TextEntryAttachment связывает присоединенные файлы к текстовым сообщениям. Содержит ссылки на основной и превью Media. 

## Как будем делать загрузку аттачментов
- на каждый аттачмент регистрируем Upload
- теперь загрузка файлов для аттачментов идёт по UploadId
- если аттачмент удалили, то надо удалить Upload путём отправки запроса на сервер
- по UploadId можно получить текущий Upload offset
- для загрузки данных файла нужно запросить от сервера текущее смещение (для новых загрузок всегда 0),
- получить чанк файла и отправить его на сервер с указанием смещения
- когда все чанки будут отправлены, сервер сам сгенерирует event, что файл загружен
- по нему надо будет закомитить Attachment
- если вся обработка на сервере, должен ли что-то делать клиент, как-то реагировать на окончание закачки?
- когда удалять сохранённый sending message?
